# Music as Medicine

Music as Medicine is a guided, music-centered web experience that helps people connect a current or future microdosing practice with intention, embodied feeling, reflection, ritual, and a rhythm of return.

The free experience is designed to be valuable on its own while also introducing users to a future premium practice platform and deeper human support through the flagship program.

> **Current phase:** Clickable validation prototype  
> **Current build:** Section 1 provisionally approved; Section 2 is next  
> **Private preview:** [music-as-medicine-prototype.myrajoi.chatgpt.site](https://music-as-medicine-prototype.myrajoi.chatgpt.site)

The hosted preview is access-restricted. The repository contains both the working prototype and the living product documentation behind it.

## Product thesis

The product journey follows a simple spine:

**Intention → Feeling → Music → Reflection → Meaning → Ritual → Rhythm → Return**

Many people begin a microdosing practice with an intention but do not have a repeatable way to stay connected to it. Music is already accessible, memorable, and emotionally meaningful. Music as Medicine helps the user turn listening from background activity into a personal practice they can revisit over time.

The app is not intended to psychologically interpret the user. It organizes and reflects the user’s own language, asks coaching questions, and keeps the user in authorship of any themes or meaning that become part of the final experience.

## Core promise

Create a playlist rooted in your microdosing intention, discover the feelings your music is awakening, and turn listening into a personal practice you can return to in rhythm over time.

## Audience

The primary audience includes people who are:

- Actively microdosing
- Preparing to begin a microdosing practice
- Looking for more intentionality or consistency
- Seeking creativity, emotional connection, self-trust, or reflection
- Interested in ritual and integration beyond protocols and schedules
- Open to deeper human guidance, community, or structured programming

Active and preparing users share the same core journey. Practice stage changes the framing and ritual language without changing access or assigning a score. Experience level changes the amount of explanation rather than the outcome.

## Intended transformation

A completed free journey can include:

- A personal playlist connected to an intention
- One or more anchor songs
- A guiding feeling and supporting feeling words
- Embodied observations connected to the music
- User-confirmed themes
- An editable Feeling Map
- An optional emotional arc for the playlist
- A personalized listening ritual
- One guided meditation
- An optional scheduled return to the ritual
- One reminder and follow-up reflection
- Journal and result exports
- An invitation to explore additional support

The first-time experience may take approximately 15–20 minutes, but this is an orientation target rather than a promise. Users do not have to listen to complete songs during playlist creation.

## Shortest meaningful path

The product should be completable with:

1. One intention
2. One guiding feeling
3. At least one song
4. One anchor-song reflection
5. User-confirmed themes
6. One editable Feeling Map
7. One listening ritual
8. An optional scheduled return
9. One save or export choice

Five to ten songs remain helpful playlist guidance, not a completion requirement. Additional songs, deeper prompts, playlist sequencing, and more reflections should enrich the result without blocking it.

## First-time journey

The complete planned journey is organized into eight phases.

| Phase | Purpose | Representative activities |
|---|---|---|
| 1. Tune in | Establish value, access, expectations, and privacy | Landing page, how it works, email access, journal-storage choice |
| 2. Name the intention | Clarify what the user is devoted to | Practice context, intention category, written intention, future-oriented reflection |
| 3. Find the feeling | Move from intention into embodied experience | Feeling family, feeling words, guiding feeling, body location and qualities |
| 4. Build the mix | Add personally meaningful music and discover curated options | Bring songs, receive recommendations, assemble a working playlist, choose anchors |
| 5. Listen inward | Explore what an anchor song awakens | Optional meditation, partial or remembered listening, body noticing, reflection |
| 6. Shape the journey | Organize user-confirmed meaning | Theme confirmation, Feeling Map, optional playlist arc, ritual creation |
| 7. Set the rhythm | Place the practice in time | Date, time, reminder choice, calendar export, rhythm confirmation |
| 8. Take it with you | Deliver value and create a next step | Completed result, export, communication choice, optional program-interest questions |

The free return loop is intended to let a user reopen the saved playlist and ritual, complete or reschedule one practice, answer one follow-up reflection, and then choose whether to continue more deeply.

## Feeling system

The feeling experience presents a broad family first and then a smaller vocabulary of specific words. Users can also add their own language.

The seven starter families are:

1. Grounding and Restoration
2. Connection and Openness
3. Courage and Agency
4. Freedom and Aliveness
5. Clarity and Creativity
6. Acceptance and Integration
7. Transformation and Awakening

For each journey, the user may select three to five feelings, name one guiding feeling, describe how it is experienced in the body, and indicate whether it feels present, longed for, or both.

The Feeling Map uses a mirror-and-confirm approach:

- The system may organize, repeat, and reflect the user’s words.
- Coaching prompts may invite the user to notice possible connections.
- The user names, confirms, edits, or removes themes.
- No psychological interpretation is presented as fact.
- No statement should enter the final map without visible user confirmation.

No AI implementation is assumed for the Feeling Map. The first version is intended to feel human, transparent, and editable.

## Music model

Users can:

- Bring their own songs
- Receive creator-curated recommendations
- Combine personal and recommended tracks
- Recall a familiar song, listen to a meaningful portion, or listen fully later
- Play music in their preferred music application and return to the experience for reflection

The first commercial release is intentionally independent of Spotify, Apple Music, and Pandora. This keeps the core experience usable without requiring a streaming account or music-service approval.

Future integrations may improve search, playlist transfer, metadata, and playback handoff, but they should enhance the experience rather than become a prerequisite.

The initial public recommendation library is expected to contain approximately 100 creator-curated songs. Community song submissions and moderation are planned for a later stage.

## Rhythm, calendar, and reminders

Time is part of the product’s central theme rather than an add-on. A completed playlist becomes more meaningful when it is connected to a ritual and placed into a gentle rhythm of return.

For the free experience:

- Scheduling is optional and highly encouraged.
- The user chooses a date and time; the app may suggest one only if the user does not choose.
- No event or reminder is created without permission.
- One active scheduled practice is available.
- The user can complete, skip, or reschedule the practice.
- One email reminder and one short follow-up reflection are planned.
- A standard external-calendar export is planned.

Premium development can later add recurring rhythms, multiple schedules, push notifications, additional practice types, connected calendars, reminder history, and patterns across journeys.

## Privacy and user authorship

Email access and journal storage are separate decisions.

An account can exist without saved journal content. For each journey, the user chooses between:

- **Saved privately:** journal responses and completed artifacts can be retained in the account.
- **Session only:** raw journal responses are not retained after the session.

At completion, a session-only user may separately choose whether to keep only the finished playlist and ritual while raw writing is removed. Calendar and reminder information must remain separate from journal content.

Marketing permission, product email, program communication, and journal storage should remain distinct choices.

## Free and premium model

### Free experience

- One complete guided journey
- User-selected and creator-curated songs
- Guided anchor-song reflection
- Starter feeling vocabulary
- Editable Feeling Map
- One listening ritual
- One guided meditation
- One scheduled practice and reminder
- External-calendar export
- PDF, email, text, copy, and device-share outputs
- Saved-private or session-only journal choice

### Premium platform

- Multiple intentions, journeys, and playlists
- Full meditation library
- Multiple facilitator voices and durations
- Expanded ritual formats and recommendations
- Voice journaling
- Continuing practice calendar
- Multiple and recurring schedules
- Email and web-push reminders
- External-calendar connections
- Follow-up check-ins
- Patterns across journeys
- Seasonal and intention-based collections
- Expanded song discovery
- Premium teaching and audio
- Payments and subscription management

The app supports independent practice. The flagship program remains the place for human guidance, structure, community, accountability, and deeper integration.

## Three build stages

### Stage 1 — Validation prototype

Purpose: validate meaning, pacing, interaction, and visual direction before investing in production systems.

Includes:

- A realistic clickable first-time journey
- Representative song recommendations
- Simulated authentication and email verification
- Simulated Feeling Map construction
- Simulated ritual and calendar scheduling
- Export previews
- No production accounts, payments, or live music integrations

### Stage 2 — First commercial release

Purpose: launch the free lead magnet as a working product and establish the first return loop.

Includes:

- Passwordless email account access
- Saved and session-only journeys
- Intention and feeling discovery
- Manual songs and approximately 100 creator-curated recommendations
- Guided anchor-song reflection
- Feeling Map and ritual assembly
- Meditation audio and transcript
- In-app calendar
- One scheduled ritual and email reminder
- External-calendar export
- PDF, email, text, copy, and device-share exports
- Follow-up reflection
- Communication permissions and program-interest capture
- Basic content management and product analytics

### Stage 3 — Premium platform

Purpose: turn the validated practice into an ongoing, monetizable membership experience.

Includes:

- Multiple journeys and saved playlists
- Recurring schedules and push notifications
- Connected external calendars
- Full meditation and ritual libraries
- Patterns over time
- Payments and subscription management
- Community contributions and moderation

## Visual direction

The design language is **retro analog editorial**, inspired by the 1980s and 1990s without becoming neon synthwave, arcade-themed, or a literal old computer interface.

Key characteristics include:

- Editorial poster compositions
- Analog music imagery
- Geometric display typography
- Warm paper-like color fields
- Bold graphic shapes
- Tactile labels, stickers, and offset shadows
- Worksheet and ruled-paper cues
- Generous negative space
- Calm journaling surfaces
- Playful details that do not obscure modern interactions

### Typography

- **Montserrat Classic:** display titles, major actions, and bold statements
- **Neue Einstellung:** body copy, prompts, labels, and supporting text

The prototype currently requests these families first and falls back to similar system fonts. Licensed webfont files have not yet been embedded.

### Core palette

| Token | Value | Intended use |
|---|---|---|
| Butter | `#f8e79a` | Warm fields and highlights |
| Paper | `#fffaf0` | Reading and writing surfaces |
| Ink | `#181516` | Text, borders, and strong contrast |
| Berry | `#d32662` | Calls to action and selected accents |
| Aubergine | `#4b173c` | Deep editorial fields |
| Blue | `#4674bd` | Labels, structure, and supporting accents |

Coral and mint remain available elsewhere in the early visual system, but the landing cassette uses only butter, paper, ink, aubergine, and blue.

The landing cassette is a fixed-proportion vector asset so its body and reels remain aligned across desktop and mobile layouts.

## Accessibility guardrails

- Retro styling must not reduce legibility.
- Body copy should use comfortable type sizes and line lengths.
- All audio should include transcripts.
- Motion should respect reduced-motion preferences.
- Analog controls should also have recognizable labels.
- Calendar categories should use text or icons in addition to color.
- Journal inputs must support keyboard, screen reader, and mobile interaction.
- Focus states should remain visible.
- Longer writing surfaces should use calm, high-contrast backgrounds.

## Running the prototype locally

### Requirements

- Node.js 22.13 or newer
- npm

### Install and start

```bash
cd prototype
npm install
npm run dev
```

Open the local address printed by the development server.

### Production-style build

```bash
cd prototype
npm run build
npm run start
```

### Available scripts

| Script | Purpose |
|---|---|
| `npm run dev` | Start the local development server |
| `npm run build` | Create the deployment build |
| `npm run start` | Run the built application locally |
| `npm run lint` | Check the project with ESLint |

The current prototype does not require environment variables. Future production capabilities will require configuration for authentication, email, storage, audio, reminders, analytics, payments, and any optional external services.

## Working method

The prototype is being built in connected vertical sections.

For each section:

1. Define only the requirements needed for that section.
2. Add the section to the responsive browser prototype.
3. Review it as an experience rather than as isolated screens.
4. Record owner decisions and revisions.
5. Mark the section provisionally approved.
6. Continue to the next section.

Earlier documents remain living sources of truth. Later design and testing decisions may require them to be revised before the MVP build specification is approved.
